# 基于 Linux 的车辆运动仿真与自动化测试系统

**Linux Vehicle Motion Simulation & Automated Testing System**

## 1. 项目简介

本项目是一个基于 Linux、C++ 和 Python 开发的简化车辆运动仿真与自动化测试系统。

项目采用 C++ 实现车辆直线运动模型，支持通过命令行设置运动速度和仿真步数，并将各时刻的运动状态输出为 CSV 文件。

使用 Python 的 `subprocess` 模块自动启动 C++ 程序，再通过 `pytest` 对正常输入、边界值、非法参数和运动轨迹进行自动化验证。

项目重点不在于复杂车辆动力学，而在于建立一套**可运行、可测试、可复现的跨语言软件测试流程**。

### 已实现功能

- C++ 简化车辆直线运动仿真
- Linux 环境下的多文件编译与运行
- 命令行速度和运动次数参数输入
- 参数格式检查、范围检查及异常处理
- CSV 车辆运动轨迹记录
- Python 自动调用 C++ 可执行程序
- CSV 轨迹读取与数据验证
- pytest 参数化自动化测试
- JUnit XML 测试报告生成

## 4. 车辆运动模型

当前项目采用一维匀速直线运动模型：

\[
x_{t+1}=x_t+v\Delta t
\]

其中：

- `x`：车辆 X 方向位置，单位 m
- `v`：车辆速度，单位 m/s
- `dt`：时间步长，当前固定为 1 s
- `steps`：运动更新次数

车辆初始位置为 `(0, 0)`，当前模型中 Y 坐标保持不变。

例如，当速度为 2 m/s、运行 5 个时间步时，理论最终位置为 10 m。

### 参数约束

| 参数 | 允许范围 |
|---|---|
| speed | 0～30 m/s |
| steps | 1～1000 |
| dt | 固定 1 s |

上述约束是当前演示模型自行设定的输入规则，不代表实际车辆的统一标准。

## 5. 编译与运行

### 环境准备

建议使用 Ubuntu 22.04 或具有兼容 C++、Python 环境的 Linux 系统。

安装基础依赖：

```bash
sudo apt update
sudo apt install g++ python3 python3-venv
```

如果 Ubuntu 22.04 提示缺少 Python 3.10 的虚拟环境组件，可安装：

```bash
sudo apt install python3.10-venv
```

### 编译 C++ 程序

在项目根目录执行：

```bash
g++ main.cpp CarModel.cpp -o car_sim
```

### 运行车辆仿真

```bash
./car_sim 2 5
```

正常运行时，程序更新车辆位置并生成 `trajectory.csv`。

查看轨迹：

```bash
cat trajectory.csv
```

预期数据示例：

```csv
time_s,x_m,y_m,speed_mps
0,0,0,2
1,2,0,2
2,4,0,2
3,6,0,2
4,8,0,2
5,10,0,2
```

CSV 包含初始状态及每一次运动更新后的状态。

## 6. Python 自动化测试

### 创建虚拟环境

在项目根目录执行：

```bash
python3 -m venv .venv
source .venv/bin/activate
```

安装 pytest：

```bash
python -m pip install pytest
```

### Python 自动调用 C++

运行：

```bash
python check_trajectory.py
```

该脚本使用 `subprocess` 启动 C++ 程序，读取生成的 CSV，并比较实际最终位置与预期结果。

### 执行 pytest

```bash
python -m pytest -v test_car_sim.py
```

测试框架自动执行多组输入，不需要手动重复启动 C++ 程序。

### 生成测试报告

```bash
mkdir -p reports

python -m pytest -v test_car_sim.py --junitxml=reports/pytest-results.xml
```

报告保存于：

`reports/pytest-results.xml`

## 8. 开发过程中发现和处理的问题

### 问题一：字符串被部分解析

**现象：** 输入 `5abc` 时，早期程序可能将其解析为整数 `5`。

**原因：** `std::stoi()` 默认允许转换字符串开头的有效数字部分。

**处理：** 使用转换位置参数 `pos` 检查字符串是否被完整解析，拒绝存在多余字符的输入。

### 问题二：非有限速度未被拒绝

**现象：** 输入 `nan` 后，仿真结果出现 `nan`。

**原因：** 普通数值范围比较无法可靠识别 NaN。

**处理：** 使用 `std::isfinite()` 增加非有限数值检查。

### 问题三：超大数值导致异常终止

**现象：** 输入 `1e309` 时，早期程序抛出未捕获的 `std::out_of_range` 异常并终止。

**处理：** 增加相应异常捕获，使程序报告参数错误并安全退出。

以上问题在 AI 辅助设计测试场景的过程中被复现，并由开发者在实际代码中修改、编译和回归验证。

## 9. AI 辅助开发与本人实际贡献

本项目采用 **AI 辅助学习与开发、开发者实际编码和测试验证** 的方式完成。

### AI 主要提供的支持

- 协助制定项目路线、分阶段目标和技术选型
- 讲解 C++、Linux、Python 和 pytest 相关知识
- 提供部分代码示例、功能实现思路和测试代码骨架
- 根据开发过程中的代码截图及报错信息分析可能原因
- 提出正常、边界和异常测试场景
- 协助分析参数转换、数值范围、异常处理等问题
- 辅助整理测试方案、项目文档及 README

AI 主要承担学习指导、方案建议、代码参考和调试辅助工作，并非独立完成项目或自动替代全部开发操作。

### 本人实际完成的工作

**1. 开发环境搭建**

在 VMware 中配置 Ubuntu 开发环境，通过 FinalShell 建立 SSH 连接，完成 g++、Python 虚拟环境及 pytest 配置，并实际执行 Linux 编译和运行命令。

**2. C++ 功能实现与调试**

在 AI 示例和指导的辅助下，亲自编写、编辑和调整车辆状态结构体、位置更新函数、循环仿真、命令行参数处理及 CSV 文件输出代码。

将 C++ 项目拆分为头文件和源文件，处理编译错误、变量作用域、条件判断及文件输出相关问题。

**3. 输入验证与缺陷修复**

通过实际运行特殊参数复现输入处理问题，修改参数范围判断、字符串完整性检查和异常捕获逻辑，并执行回归测试确认修复效果。

**4. Python 测试脚本开发**

在参考 AI 代码示例的基础上，亲自编写和整合 `subprocess` 调用、CSV 数据读取、实际结果与预期值比较等逻辑。

**5. pytest 测试执行与验证**

参考 AI 提供的参数化测试方法和测试场景，在本地测试文件中完成用例配置、断言修改及逐时刻轨迹校验。

多次实际运行 pytest，处理 Python 缩进、语法和测试组织问题，并最终验证 12 组用例全部通过。

**6. 测试结果归档**

在 Ubuntu 中实际执行测试命令，生成 JUnit XML 测试报告，并检查报告文件是否存在。

### 对 AI 辅助开发的理解

本项目中，AI 提高了资料查找、知识理解、代码调试和测试设计的效率，但程序是否能够编译、功能是否满足要求、测试是否通过，均以实际开发环境中的运行结果为依据。

项目保留 AI 辅助开发的事实，不将参考代码、AI 建议或未经执行的测试场景描述为完全独立完成的工作成果。

## 10. 项目局限性

当前版本仍是用于学习和测试流程验证的简化软件模型，存在以下限制：

- 仅支持一维匀速直线运动
- 时间步长固定为 1 秒
- 未实现转向、加速度控制和车辆动力学
- 未接入真实 ECU、CAN 硬件或车辆传感器
- 未进行真实道路测试或车规级验证
- 尚未完成持续集成及跨平台兼容性验证
- 测试用例覆盖当前明确的功能和部分异常输入，不代表穷尽全部边界情况
